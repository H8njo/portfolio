2020년, 코로나19가 전 세계를 뒤흔들던 시절 React Native로 만들었던 위치 기반 모바일 앱이다.

내 현재 위치 반경 2km 이내의 확진자 이동 동선과 지역 위험도를 지도와 슬라이딩 카드로 실시간 시각화해 주는 서비스였다. 100여 개에 달하는 커밋 중 가장 많은 고민과 시간을 쏟았던 곳은 단 하나의 핵심 지도 컴포넌트(`Map.js`, 580줄)였다.

지도를 확대하고 축소할 때마다 마커의 형태와 정보 밀도가 완전히 바뀌는 인터랙티브 맵이었다.

## 1. 문제: 화면을 덮어버리는 수백 개의 핀과 라이브러리의 한계

확진자 한 명이 수십 곳의 동선을 남기다 보니, 지도를 조금만 축소해도 화면 전체가 핀으로 새까맣게 뒤덮였다.

처음에는 당연히 기성 클러스터링 라이브러리(`react-native-map-clustering`)를 설치해 적용했다. 하지만 곧 벽에 부딪혔다. 내가 원했던 것은 단순히 **핀 여러 개를 묶어 동그라미 숫자(예: +15)로 뭉개는 것**이 아니었다:

- **1단계 (확대)**: 개별 장소별 상세 동선 핀 + 하단 상세 카드
- **2단계 (중간)**: 행정구역(구) 단위의 확진자 밀도 및 위험도 핀 + 통계 카드
- **3단계 (축소)**: 단순 점(Dot) 마커로 전체적인 분포만 암시

줌 레벨에 따라 마커의 **종류와 성격 자체가 완전히 달라지는 3단 변환**이 필요했다. 기성 클러스터링 라이브러리의 추상화 위에 이 특화된 동작을 얹으려다 보니 끝없는 라이브러리 내부 해킹과 버그가 발생했다.

## 2. 해결책: 라이브러리를 걷어내고 `latitudeDelta` 기반 줌 역산

라이브러리의 추상화와 씨름하는 시간을 멈추고, 과감히 라이브러리를 걷어낸 뒤 **지도의 뷰포트 변화(`latitudeDelta`)로부터 직접 줌 레벨을 역산하는 단순한 규칙**을 세웠다:

```js
const LEVEL_1_LIMIT = { latitudeDelta: 0.052 };
const LEVEL_2_LIMIT = { latitudeDelta: 0.448 };

// 지도가 멈추는 시점(onRegionChangeComplete)에 줌 레벨을 3단계로 분기
const convertZoomLevel = ({ latitudeDelta }) => {
  if (LEVEL_1_LIMIT.latitudeDelta > latitudeDelta) return 1; // 1단: 상세 동선 핀
  if (LEVEL_2_LIMIT.latitudeDelta > latitudeDelta) return 2; // 2단: 구 단위 위험도 핀
  return 3;                                                 // 3단: 단순 점 마커
};
```

복잡한 외부 의존성을 걷어내고 임계값 2개로 제어하는 10줄의 순수 코드로 전환하자, 마커 전환 로직이 놀랍도록 직관적이고 가벼워졌다.

### 애니메이션 및 레이아웃 타이밍 방어
1. **줌 애니메이션 중복 진입 차단**: 줌 인/아웃 버튼을 연속 클릭할 때 카메라 이동이 중첩되어 지도가 튀는 현상을 막기 위해, 애니메이션 실행 플래그(`state.animating`)로 호출을 가드했다.
2. **지도 레이아웃 준비 게이트**: `MapView`의 실제 컨테이너 측정이 완료되기(`onLayout`) 전에 마커를 렌더링하면 좌표가 엉뚱한 곳에 찍히는 문제를 방지하기 위해 `isMapReady` 플래그가 켜진 뒤에만 마커를 그리도록 제어했다.
3. **Android Release 빌드 크래시 해결**: 디버그에서는 정상이지만 릴리스 빌드에서만 SVG 렌더링 시 크래시가 발생하는 현상을 추적하여, ProGuard 난독화 규칙에 `-keep` 설정을 추가하여 네이티브 모듈을 보호했다.

## 결과

* **양대 앱스토어 출시**: iOS App Store와 Google Play Store에 '두기두기'라는 이름으로 정식 출시하여 실제 유저들에게 위치 기반 방역 정보를 제공했다.
* **부드러운 3단 마커 인터랙션**: 지도를 축소/확대할 때 핀이 깜빡임 없이 '동선 핀 → 구 위험도 → 점'으로 유려하게 전환되는 가벼운 모바일 지도 UX를 완성했다.

## 회고: 잘한 결정과 어린 결정이 함께 남긴 배움

클러스터링 라이브러리를 걷어낸 결정은 지금 돌이켜보아도 훌륭한 엔지니어링 판단이었다. **기성 라이브러리의 거대한 추상화가 내가 풀려는 문제의 본질과 맞지 않을 때는, 프레임워크와 씨름하는 대신 핵심 규칙 몇 줄을 직접 정의하는 편이 훨씬 빠르고 견고하다.**

반면 상태 관리 설계는 성장통이 담긴 반성의 기록이다. 당시에는 `redux-thunk` 대신 커스텀 Redux 미들웨어로 비동기 호출을 직렬화했는데, 그 미들웨어 안에 Firestore 쿼리 조립, 내 위치와의 거리 계산, 위험도 산출 등 비즈니스 로직이 한꺼번에 엉켜 들어갔다.

세월이 흘러 과거의 코드를 다시 열어보았을 때, 현명했던 결정과 미숙했던 설계가 함께 공존하는 것을 보며 **엔지니어로서 내가 얼마나 깊어지고 성장했는가**를 온몸으로 실감할 수 있었던 소중한 첫걸음이었다.
