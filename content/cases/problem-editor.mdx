영어 지문 위에 얹는 시각적 표시들은, 줄바꿈 한 번이면 전부 깨져버렸다.

교육 콘텐츠 제작 플랫폼의 **본문 문장분석 에디터**를 개발했다. 영어 지문 위에 밑줄, 하이라이트, 도형 박스, 단어 간 연결 화살표, 부동 메모 등 10여 종의 시각적 주석을 얹어 교재를 만드는 핵심 도구였다. 화면은 크게 둘로 나뉜다. 왼쪽은 실시간 지문 미리보기 뷰어, 오른쪽은 주석의 세부 속성을 설정하는 편집 패널이다.

## PO 공석에서 주도한 GUI 에디터 전면 혁신

당시 기획자(PO)가 공석인 상황이었다. 나는 교재를 직접 제작하는 검수자(실사용자)들의 작업실을 찾아가 그들이 겪는 고통을 직접 듣고, 기획부터 UI 디자인, 프론트엔드 개발까지 전 과정을 주도했다.

기존의 작업 방식은 충격적일 정도로 비효율적이었다. 검수자들은 복잡한 JSON 데이터 구조와 지문 내 단어 인덱스(예: `[12, 18]`)를 일일이 세어서 텍스트 창에 직접 타이핑하고 있었다. 오타가 나거나 단어 하나만 밀려도 전체 주석이 엉뚱한 위치에 붙어 검수 피로도가 극에 달해 있었다.

이를 **단어를 클릭(시작점) → 다시 클릭(끝점)하는 것만으로 범위를 지정하고 주석을 실시간 편집·삭제할 수 있는 직관적인 인터랙티브 GUI 에디터**로 전면 재설계했다.

## 근본 원인: BE/ML의 통 HTML 결합에서 데이터 구조의 분리로

하지만 직관적인 UI를 구현하기에 앞서, 가장 먼저 부딪힌 거대한 장벽은 **백엔드(BE)와 머신러닝(ML) 엔진의 통 HTML 데이터 결합**이었다.

기존 시스템은 백엔드와 ML 파이프라인에서 스타일 클래스가 인라인으로 덕지덕지 붙은 **거대한 통 HTML 문자열을 그대로 프론트엔드에 내려주는 방식**이었다. 이 구조에서는 프론트엔드가 백엔드와 ML이 정해둔 고정된 룰에 일방적으로 끌려다녀야 했고, 문장을 단락별로 자유롭게 나누거나 데코레이터를 유연하게 제어하는 것이 구조적으로 불가능했다.

나는 팀에 "이 구조 자체를 바꿔야 한다. 글자는 글자대로, 데코레이터는 데코레이터대로 분리되어야 한다"고 지속적으로 목소리를 냈다. 그리고 마침 이번 신규 에디터 프로젝트를 전담하게 되면서, **데이터 구조 자체를 근본적으로 바꿀 수 있는 절호의 기회**를 잡았다.

BE/ML 팀을 적극 설득하여 통 HTML 주입 방식을 폐기하고, 데이터를 완벽히 두 축으로 분리하도록 스키마를 재설계했다:
1. **순수 본문 텍스트 (Text Tokens)**: 스타일 없이 순수한 글자와 공백으로 분해된 단어 배열.
2. **시각적 데코레이터 메타데이터 (Decorators)**: 데코레이터의 종류(밑줄, 박스, 화살표, 메모)와 대상 단어들의 인덱스(`targetWordIndices: [12, 13, 14]`), 속성만을 담은 독립된 메타데이터 배열.

데이터와 시각적 표현의 책임을 명확히 가르자, 프론트엔드가 렌더링과 인터랙션의 완전한 주도권을 쥐게 되었다.

## 줄바꿈이 모든 시각적 주석을 깨뜨린다

데이터 구조를 분리한 후 마주한 다음 렌더링 난제는 바로 **줄바꿈**(Line Break)이었다.

주석이 한 줄 안에 온전히 들어갈 때는 간단하다. 단어 좌표 위에 선을 긋거나 박스를 씌우면 그만이다.

진짜 문제는 사용자가 선택한 범위가 **줄 끝에서 다음 줄로 넘어갈 때** 발생했다:
- **밑줄/하이라이트**: 단어마다 개별적으로 칠하면 단어 사이의 띄어쓰기 공백에서 선이 뚝뚝 끊겨 보인다.
- **도형(박스)**: 사각형은 양쪽 변을 지우면 되지만, 타원이나 삼각형은 반쪽짜리 도형을 따로 그릴 수 없다.
- **화살표**: 서로 다른 줄에 위치한 두 단어를 연결할 때 직선이 아닌 다단으로 꺾인 형태를 자연스럽게 이어야 한다.
- **부동 메모**: 여러 줄에 걸친 문장 중 어느 줄의 중앙에 띄워야 할지, 줄 간 여백은 어떻게 확보할지 결정해야 한다.

게다가 줄바꿈은 고정된 위치가 아니다. 편집 패널의 너비를 조절하거나, 창 크기가 바뀌거나, 웹 폰트가 로드되는 순간 동일한 문장도 단어들의 줄바꿈 위치가 실시간으로 재배치된다.

## 발상의 전환: 통문장 `<p>`에서 단어별 `<span>` 토큰 분해로

단어를 실측하려면 가장 먼저 **DOM 구조 자체를 혁신**해야 했다.

기존에는 `<p>` 태그 안에 전체 문장이 하나의 거대한 통 텍스트 노드로 뭉쳐 들어가 있었다. 이 구조에서는 브라우저가 개별 단어의 바운딩 박스(좌표와 너비·높이)를 자바스크립트로 측정할 방법이 전혀 없었다.

그래서 문장을 공백(띄어쓰기)을 기준으로 잘라내어, **모든 단어를 인덱스가 부여된 개별 `<span>` 태그로 감싸 렌더링하는 토큰화 구조**로 전면 전환했다:

```jsx
// 기존: 통문장이라 단어별 위치를 알 수 없음
<p>The quick brown fox jumps over the lazy dog</p>

// 개선: 단어별 span 분해 → 각 단어의 DOM 좌표 실측 및 데코레이터 앵커 확보
<p>
  <span data-word-idx="0">The</span>{" "}
  <span data-word-idx="1">quick</span>{" "}
  <span data-word-idx="2">brown</span>{" "}
  ...
</p>
```

문장 구조를 이렇게 잘게 쪼개어 놓자 놀라운 변화가 생겼다:
1. **단어별 정밀 좌표 측정**: `getBoundingClientRect()`를 통해 화면에 그려진 단어 하나하나의 픽셀 좌표와 뷰포트 상대 위치를 오차 없이 실측할 수 있게 되었다.
2. **데코레이터 조작의 자유도**: 밑줄, 박스, 화살표, 뱃지 같은 시각적 데코레이터들이 특정 단어 엘리먼트를 앵커(Anchor) 삼아 훨씬 유연하고 정밀하게 화면을 가지고 놀 수 있는 토대가 마련되었다.

## 핵심 원리: 단어 실측 기반의 '줄 지도(Line Map)' 구축

해결의 토대는 분해된 단어들의 정밀 실측이었다. 화면에 렌더링된 모든 단어 `<span>` 엘리먼트의 좌표(top, left, width, height)를 측정하고, 세로 위치(top)가 일치하는 단어들을 하나의 줄로 묶어 **동적 줄 지도**(Line Map)를 생성했다.

```ts
// 렌더링 시 단어의 미세한 baseline 오차를 보정하기 위해 tolerance 적용
if (Math.abs(word.top - lineTop) <= LINE_TOLERANCE) {
  // 동일한 줄(Line)로 판정하고 단어 묶음에 추가
}
```

이렇게 단어마다 "몇 번째 줄에 속하는지", "그 줄의 시작점인지 끝점인지"를 매핑해두면, 10여 종의 모든 시각적 주석이 이 줄 지도를 기반으로 자신의 모양을 스스로 분해하고 이어 붙인다.

## 10종의 표시마다 줄바꿈 알고리즘을 독립 설계

주석의 종류마다 '줄을 넘어갈 때 자연스러운 시각적 형태'가 완전히 달랐기에, 줄바꿈 대응 로직을 유형별로 독립 분리했다.

![줄바꿈을 가로지르는 표시들 — 밑줄은 띄어쓰기까지 잇고, 타원은 줄을 넘어 잘리고, 화살표는 두 줄에 걸쳐 꺾인다.](/cases/sentence-analysis.png)

1. **밑줄·하이라이트 (연속 바 렌더링)**:
   단어별로 칠하지 않고, 줄 지도를 기준으로 **해당 줄의 첫 단어 왼쪽 끝부터 마지막 단어 오른쪽 끝까지 연속된 단일 바**를 그린다. 이를 통해 띄어쓰기 공백에서도 선이 끊기지 않고 매끄럽게 이어진다. 줄 끝에 걸친 괄호나 문장부호까지 인식해 어정쩡하게 글자 직전에서 멈추지 않도록 영역을 확장했다.

2. **도형 박스 (중심점 이동과 `clip-path` 트릭)**:
   타원이나 삼각형이 줄바꿈으로 나뉠 때, 잘린 반쪽짜리 도형을 억지로 그리는 대신 **도형 전체를 온전히 그리되 중심점(`cx`)을 이동시키고 해당 줄 영역만큼만 잘라내는(clip) 방식**을 고안했다.
   - 첫 줄: 타원의 중심을 줄 오른쪽 끝으로 이동 → **왼쪽 반원만 노출**
   - 다음 줄: 중심을 줄 왼쪽 끝으로 이동 → **오른쪽 반원만 노출**
   - 시각적으로는 하나의 완벽한 타원이 줄을 넘어 자연스럽게 이어져 보이는 효과를 완성했다.

3. **다단 연결 화살표**:
   두 단어가 서로 다른 줄에 있을 경우, 시작 줄(시작점 → 줄 끝), 중간 줄(줄 전체 너비), 끝 줄(줄 시작점 → 도착점)의 3개 세그먼트로 연결선을 토막 내어 매끄럽게 꺾이도록 렌더링했다.

4. **부동 메모 (밀도 기반 배치 & 스택 여백)**:
   여러 줄에 걸친 범위일 경우 단어가 가장 밀집된 줄을 찾아 그 중앙에 메모를 띄우고, 화면 밖으로 벗어나지 않도록 좌우 경계를 `clamp` 처리했다. 한 위치에 메모가 여러 개 겹치면 위로 차곡차곡 쌓으며 해당 줄의 상단 마진을 동적으로 확보했다.

## 실시간 렌더링 흔들림을 잡는 2-Pass 파이프라인

줄 지도는 정적이지 않고 수시로 흔들렸다. 밑줄이나 메모가 추가되면 그 여백 때문에 단어들의 세로 위치가 미세하게 밀려났다.

* **2-Pass 렌더링 루프**: 1차 렌더링 후 메모와 주석 여백이 DOM에 적용되면 다음 프레임에 위치를 한 번 더 재측정하여 오차를 완전히 제거했다.
* **다중 관찰자 연동**: `ResizeObserver`로 컨테이너와 패널 크기 변화를 실시간 감지하고, 웹 폰트 로드 완료 시점(`document.fonts.ready`)과 `window.resize` 이벤트를 묶어 레이아웃이 바뀔 때마다 줄 지도를 즉각 갱신했다.
* **사파리(Safari) 잔상 버그 해결**: 밑줄 페이드 트랜지션 시 사파리 엔진에서만 렌더링 잔상이 남는 문제를, 해당 엘리먼트에 `translateZ(0)`과 `will-change`를 주어 독립 GPU 레이어로 승격시켜 해결했다.
* **드래프트 상태 격리**: 검수 중인 임시 편집 데이터는 별도의 `draft store`로 격리하여 본문 미리보기가 오염되지 않도록 관리했다.

## 결과

* **업무 생산성 극대화**: 신규 검수자가 더 이상 복잡한 JSON 스키마와 단어 번호를 외울 필요 없이, 마우스 클릭-클릭 조작만으로 교재 문장을 직관적으로 검수하고 분석할 수 있게 되었다.
* **10종 데코레이터의 완벽한 렌더링**: 텍스트와 데코레이터가 분리된 구조 위에서, 줄바꿈과 패널 리사이즈 등 어떤 반응형 환경에서도 10종의 시각적 주석이 의도된 대로 완벽하게 렌더링되었다.
* **전사 핵심 프로젝트로의 데이터 표준화 마이그레이션**: 이 분리 아키텍처의 성공과 렌더링 안정성이 회사 전체에서 인정받아, **기존의 레거시 핵심 서비스들까지 이 데이터 스키마로 데이터를 전면 마이그레이션하고 재설계하는 거대한 표준화의 계기**가 되었다.

## 회고

이 프로젝트에서 가장 깊게 배운 것은 **데이터 모델의 단위와 화면에 렌더링되는 시각적 단위 사이의 거대한 간극을 메우는 방법**이었다.

데이터 관점에서는 "특정 단어 인덱스 배열"이라는 단순한 숫자 쌍이었지만, 실제 사용자 눈앞에 보여야 하는 것은 줄바꿈과 공백, 폰트 렌더링을 유연하게 넘나드는 하나의 연속된 기하학적 형태였다.

백엔드의 통 HTML 결합을 깨부수고 **글자와 데코레이터의 메타데이터를 분리한 아키텍처 결단**, 그리고 **브라우저의 실제 렌더링 결과를 측정하여 따라가는 반응형 렌더링 엔진**이 결합되었기에 전사적 표준으로 자리 잡을 수 있었다.
