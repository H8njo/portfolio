{/* 사내 프로젝트: Solvook Delta ML 파싱 고밀도 검수 콘솔 SPA. */}

"도저히 이 툴로는 답답해서 일을 못 하겠다. 내가 빠르게 작업할 툴을 직접 만들자."

프로젝트의 시작은 단순한 개발 티켓이 아니라, **내가 직접 교재 데이터 검수 실무를 맡게 되면서 겪은 극심한 불편함**에서 출발했다.

AI/ML 모델이 수백 페이지의 교재 PDF를 분석하여 추출한 텍스트 영역(BBOX), 문항과 지문 구조(ITEM), 메타데이터를 사람이 직접 눈으로 확인하고 교정하는 작업이었다.

하지만 기존에 쓰이던 오픈소스 AdminJS 어드민 화면은 실무 작업자에게는 '고문'에 가까웠다:
- 문항 하나를 확인하려면 마우스로 목록을 뒤지고, 상세 페이지로 들어가고, 탭을 누를 때마다 화면 전체가 덜컹거리며 다시 로드되었다.
- 불필요한 장식과 눈부신 흰색 여백, 복잡한 뎁스 탓에 **숙련된 기존 작업자들도 하루 최대 1,000개 문항을 검수하는 것이 물리적인 한계치**였다.

내가 맡은 검수 업무를 빠르게 끝내고 반복작업의 고통을 없애기 위해, 백엔드 의존 없이 브라우저에서 날아다니는 **초경량 React 19 기반 고밀도 검수 SPA**를 자발적으로 구축하기 시작했다.

## 1. 가장 큰 제약: 백엔드에 전용 JSON API가 없다

기존 백엔드 개발팀에 "새 SPA를 위한 전용 REST API를 만들어달라"고 요청할 리소스가 없었다. 즉, **기존 백엔드가 AdminJS 어드민 화면을 렌더링하기 위해 쓰던 세션 쿠키 기반의 리소스 액션 엔드포인트들을 그대로 호출해 재사용해야 하는 강력한 제약**이 있었다.

겉으로는 평범한 HTTP 호출처럼 보였지만, 내부에는 브라우저 SPA 표준을 깨뜨리는 수많은 지뢰가 숨어 있었다:

### ① 미인증 302 HTML 리다이렉트의 함정
인증 세션이 만료되면 일반적인 API 서버처럼 `401 Unauthorized`를 뱉지 않고, HTTP 302로 `/admin/login` 로그인 HTML 페이지를 응답했다. 브라우저의 `fetch`는 302를 자동으로 따라가 **HTTP 200 상태코드와 함께 거대한 HTML 문자열**을 반환했다. 상태코드만 검사하는 일반적인 HTTP 클라이언트는 "요청이 성공했다"고 착각하여 JSON 파싱 런타임 에러를 터뜨렸다.

### ② HTTP 200 속에 숨겨진 실패 알림
권한이 없거나 유효성 검증에 실패했을 때도 백엔드는 `400`이나 `403`을 뱉지 않고 **HTTP 200 OK와 함께 `{ notice: { type: 'error' } }` 알림**을 내려주었다. 에러가 성공의 탈을 쓰고 들어오는 구조였다.

### ③ 임시방편: 전용 API 신설 전까지의 임시 가교 래퍼 (`adminAction`, `adminMutation`)
물론 이 래퍼는 영구적인 아키텍처가 아니라, **추후 백엔드에 정식 전용 REST API가 구축되면 즉시 교체될 예정인 임시 가교**(Stopgap Bridge)다.

하지만 백엔드 개발이 끝날 때까지 마냥 손 놓고 기다릴 수는 없었기에, 비표준 동작을 단일 모듈 안에 완벽히 격리했다:

```ts
// src/api/adminAction.ts — AdminJS의 비표준 동작을 정규화하는 임시 래퍼
export async function adminAction<T>(url: string): Promise<T> {
  const res = await fetch(url, { credentials: 'include' });

  // 1. 302 로그인 HTML 리다이렉트 인터셉트
  const contentType = res.headers.get('content-type') || '';
  if (!contentType.includes('application/json') || res.url.includes('/admin/login')) {
    throw new SessionExpiredError('세션이 만료되었습니다.');
  }

  const json = await res.json();

  // 2. HTTP 200 속에 숨은 notice: error를 정규 에러로 승격
  if (json?.notice?.type === 'error') {
    throw new AdminActionError(json.notice.message);
  }

  return json as T;
}
```

미인증 HTML 응답은 즉시 `SessionExpiredError`로 분기시켜 재시도 루프 없이 로그인 가드로 유도하고, `notice: error`는 `AdminActionError`로 자동 승격하여 TanStack Query의 표준 에러 바운더리가 자연스럽게 감지하도록 정규화했다.

이렇게 호출부를 깔끔히 캡슐화해 둔 덕분에, **향후 백엔드에 정식 API가 나오더라도 UI 컴포넌트는 한 줄도 건드릴 필요 없이 이 래퍼 함수 하나만 표준 API 클라이언트로 갈아끼우면 되는 확장성**을 확보했다.

## 2. 편집 중 데이터 유실을 막는 캐시 무효화 전략 (`staleRecordCaches`)

검수 작업은 BBOX(영역), ITEM(문항), METADATA 세 개의 탭으로 나뉘어 진행된다. 이 세 탭은 서로 다른 화면이지만 **데이터베이스 상으로는 동일한 하나의 자료 레코드**를 공유한다.

여기서 치명적인 동시성 문제가 도사리고 있었다:

1. 작업자가 한 탭에서 장시간 오타를 수정하고 있는데, 백그라운드에서 TanStack Query가 `stale` 상태를 감지하고 데이터를 다시 패칭해 오면 **작성 중이던 편집 내용이 서버 데이터로 덮어씌워져 날아갈 위험**이 있었다.
2. 반대로 저장을 방지하기 위해 캐시 재조회를 막아두면, BBOX 탭에서 저장한 변경사항이 ITEM 탭을 열었을 때 반영되지 않는 데이터 불일치가 발생했다.

이를 해결하기 위해 정교한 **지연 무효화(Deferred Invalidation) 전략**을 수립했다:

- **작업 중 평화 유지**: 세 탭의 모든 조회 쿼리에 `staleTime: Infinity`를 부여하여, 작업자가 화면을 열고 있는 동안에는 어떤 백그라운드 네트워크 폴링도 일어나지 않게 고정했다.
- **저장 시 `refetchType: 'none'` 무효화**: 저장이 완료되면 관련 4개 캐시 키(item, metadata, bbox, detail)를 즉시 무효화하되, `refetchType: 'none'`을 선언했다.

```ts
// 저장 완료 시 현재 화면을 흔들지 않고 캐시만 만료 상태로 표시
export function staleRecordCaches(queryClient: QueryClient, recordId: string) {
  queryClient.invalidateQueries({
    queryKey: ['record', recordId],
    refetchType: 'none', // ⚠️ 즉시 백그라운드 재패칭을 하지 않는다!
  });
}
```

수 메가바이트의 거대한 문항 데이터를 편집 중인 화면 밑에서 다시 다운로드하는 낭비를 없애고, **작업자가 실제로 다음 탭을 열거나 다른 화면으로 이동하는 순간에만 최신 데이터가 깨끗하게 마운트**되도록 생명주기를 정렬했다.

## 3. 하루 8,000건을 가능하게 만든 2가지 무기

### ① 대용량 PDF 위의 60fps Konva BBOX 캔버스
수백 페이지 교재 위에서 텍스트와 이미지 영역을 밀리미터 단위로 미세 조정해야 했다. DOM 요소 수백 개를 직접 렌더링하면 브라우저가 버벅거렸기에, `pdfjs-dist`로 렌더링된 배경 캔버스 위에 **`react-konva` 기반의 하드웨어 가속 2D 캔버스 레이어**를 얹었다.

영역 간 충돌 판정(`bboxGeometry.ts`), 키보드 기반 Undo/Redo 히스토리 스택, 드래그 다중 선택 및 카테고리 일괄 할당을 네이티브 데스크톱 앱 수준의 60fps로 매끄럽게 처리했다.

### ② 마우스를 놓게 만드는 연속 검수 큐 (Review Automation)
작업자가 한 문제를 검수할 때마다 [목록으로 나가기 → 다음 항목 클릭 → 상세 진입]을 반복하는 병목을 완전히 파괴했다:
- **STEP 1**: 대시보드에서 오늘 검수할 교재들을 클릭하여 로컬 큐에 담는다 (`Zustand/persist` 기반).
- **STEP 2**: 단축키(`⌥ →`) 하나만 누르면 현재 문항 저장을 완료하고 화면 이동 깜빡임 없이 즉시 다음 문항 캔버스로 직행한다.

마우스에 손을 댈 필요 없이, 키보드 단축키만으로 수백 개의 문항을 끊김 없이 논스톱 검수하는 워크플로우를 완성했다.

## 4. 8시간을 응시하는 작업자를 위한 산업용 웜 브라운 디자인 시스템

눈의 피로를 최소화하는 **Industrial Utilitarian 디자인 시스템**을 직접 설계했다:

- **순백과 순검정 금지**: 차가운 블루라이트를 유발하는 `#FFFFFF`와 `#000000`을 코드베이스에서 영구 차단하고, 종이 질감의 따뜻한 황갈색 톤(`#F7F2EA` Canvas, `#241C13` Ink)을 베이스로 확립했다.
- **엄격한 4색 상태 예산과 실루엣 보장**:
  - 처리 필요: `#B63C0A` (Action Rust)
  - 실패/재실행: `#5E0C1B` (Fail Wine) · `■` 실루엣
  - 작업 완료: `#1D4ED8` (Work Done Blue) · `●` 실루엣
  - 검수 완료: `#136B33` (Review Done Green) · `✓` 실루엣
- 색약 작업자도 한눈에 구별할 수 있도록 모든 상태에 색상뿐만 아니라 고유한 기하학 실루엣(`■`, `●`, `✓`)을 필수로 결합했다.

## 결과: 하루 1,000건에서 8,000건으로 8배 폭증한 생산성

* **일일 검수량 8배 폭증 (1,000건 → 8,000건)**: 마우스 클릭 지옥을 없애고 `⌥ →` 단축키 기반 연속 큐 시스템과 60fps Konva 캔버스를 구축한 결과, 기존 작업자들의 하루 최대 한계치(1,000건)를 훌쩍 뛰어넘어 **혼자서 하루 최대 8,000건의 문항을 초고속으로 검수**해내는 압도적인 생산성을 달성했다.
* **비표준 백엔드 제약의 완벽한 캡슐화**: 전용 REST API가 없는 AdminJS 레거시 환경 위에서도, 단 한 줄의 UI 코드 오염 없이 견고한 세션 관리와 에러 핸들링을 갖춘 독립 React 19 SPA를 성공적으로 안착시켰다.
* **작업 데이터 유실 0건 달성**: `staleTime: Infinity`와 `refetchType: 'none'` 조합의 지연 무효화 전략을 통해, 장시간 편집 중 데이터가 덮어씌워지거나 유실되는 동시성 사고를 100% 방어했다.

## 회고: 최고의 도구는 현장의 고통에서 태어난다

직접 검수 실무를 경험해보지 않았다면, "어드민이 원래 좀 느리고 불편하지"라며 넘어갔을지도 모른다.

하지만 내가 직접 사용자가 되어 하루 종일 화면을 붙잡고 일해보았기에, 작업자를 지치게 만드는 1초의 화면 덜컹거림과 불필요한 마우스 동선이 얼마나 거대한 생산성 낭비인지를 뼈저리게 체감할 수 있었다.

**현장의 고통에 깊이 공감하고, 제약에 굴하지 않고 스스로 시스템을 뒤집어 도구를 만들어내는 실행력**이 엔지니어링을 단순한 코딩을 넘어 비즈니스의 압도적인 경쟁력으로 바꾸는 힘임을 증명한 가장 뿌듯한 프로젝트였다.
