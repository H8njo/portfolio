"도저히 이 툴로는 답답해서 일을 못 하겠다. 내가 빠르게 작업할 툴을 직접 만들자."

프로젝트의 시작은 단순한 개발 티켓이 아니라, **내가 직접 교재 데이터 검수 실무를 맡게 되면서 겪은 극심한 불편함**에서 출발했다.

AI/ML 모델이 수백 페이지의 교재 PDF를 분석하여 추출한 문항, 지문, 선지, 메타데이터를 사람이 직접 눈으로 확인하고 교정하는 작업이었다.

하지만 기존 시스템의 UX는 실무 작업자에게는 '고문'에 가까웠다:
- PDF 원본과 입력 폼을 눈이 빠져라 번갈아 대조하면서 파싱이 잘 되었는지 확인해야 했다.
- 구두점 탈락, 괄호 누락, 오탈자 같은 오류들을 작업자가 본문을 샅샅이 뒤져가며 찾아내 하나씩 타이핑해 고쳐야 했다.
- 교재 한 권을 보려면 목록을 뒤지고, 상세 페이지에 들어가고, 상태 변경 페이지를 따로 찾아가고, 메타데이터 화면을 다시 켜야 하는 등 **화면 이곳저곳을 끝없이 헤매는 동선 낭비**가 심각했다.
- 흐릿한 밑줄이나 번호 원기호(①, ②, ③)가 잘 보이지 않아 눈을 찡그리고 확인하느라 작업 피로도가 극에 달했고, **숙련된 기존 작업자들도 하루 최대 1,000개 문항을 검수하는 것이 물리적인 한계치**였다.

내가 맡은 검수 업무를 빠르게 끝내고 반복작업의 고통을 없애기 위해, **작업자가 오류를 찾으려 애쓰지 않고, 화면을 헤매지 않아도 되는 초고속 UX**를 목표로 새로운 고밀도 검수 SPA를 직접 설계하고 구현했다.

## 1. 눈으로 오류를 찾던 시대를 끝낸 '마법봉(Magic Wand)' 원클릭 시스템

가장 큰 병목은 "어디가 틀렸는지 눈으로 찾고 손으로 고치는 시간"이었다.

교재 파싱에서 발생하는 오류는 대부분 정형화된 패턴(구두점 누락, 괄호 짝 불일치, 불필요한 줄바꿈, 선지 번호 밀림 등)을 가지고 있었다. 이를 사람이 직접 찾게 두는 대신, 시스템이 백그라운드에서 실시간으로 감지하도록 규칙 엔진을 설계했다.

### ① 불이 켜지는 마법봉 뱃지
- 문항 내 텍스트 블록에 교정이 필요한 오류가 감지되면, 해당 영역 제목 옆과 상단 툴바의 **마법봉 아이콘에 선명한 오렌지색 불**(교정 대상 개수 뱃지)이 들어온다.
- 작업자는 화면 어디가 틀렸는지 긴장하며 찾을 필요 없이, **불이 켜져 있는가**만 확인하면 된다.

### ② 툴바 원클릭 일괄 교정
문항마다 수십 개의 블록을 일일이 누르는 것도 낭비였다. 상단 툴바의 마법봉 버튼 하나를 '딸깍' 누르면, **불이 켜진 모든 블록의 오류 조각들이 표준 규격으로 한 번에 일괄 변환**(AST/HTML Transform)된다.

작업자는 불 켜진 마법봉을 한 번 누른 뒤 변환 결과를 눈으로 슥 확인하기만 하면 검수가 끝나는 혁신적인 워크플로우를 완성했다.

## 2. 룰과 엑셀을 결합한 '메타데이터 출처 스마트 자동 매칭'

문항 검수 외에 작업자의 발목을 잡던 또 다른 복병은 교재의 단원, 출처, 저작권 정보를 일일이 입력하는 메타데이터 작업이었다.

기존에는 별도의 엑셀 시트나 문서를 열어두고 문항마다 출처 코드를 복사해서 붙여넣어야 했다. 이를 2단계 자동화 파이프라인으로 전환했다:

1. **1차 룰 기반 자동 적용**: 규칙성이 뚜렷한 출처 패턴은 사전에 정의된 정규 룰 엔진을 통해 문항 생성 시점에 100% 자동 매핑했다.
2. **2차 엑셀 기반 스마트 검색 & 마법봉 매칭**: 룰에 걸리지 않는 비정형 예외 문항들은 사전에 업로드된 기준 엑셀 데이터를 바탕으로 검색 및 퍼지 매칭을 수행했다. 작업자가 검색창을 뒤질 필요 없이, 추천된 매칭 후보를 **마법봉 클릭 한 번으로 메타데이터 폼에 즉시 일괄 바인딩**하도록 구축했다.

## 3. 0.1초 만에 인지하게 만든 PDF 시각 보조 도구 (밑줄 & 원기호 강조)

검수 속도를 떨어뜨리는 사소하지만 결정적인 원인은 "PDF 원본의 가독성"에 있었다.

교재 특성상 문맥을 파악하기 위해 핵심이 되는 작은 밑줄이나 번호 원기호(①, ②, ③, ④, ⑤)가 인쇄 해상도나 축소 뷰포트에 따라 흐릿하게 뭉개져 보여, 작업자가 화면을 확대/축소하며 확인하느라 많은 시간을 허비하고 있었다.

- **PDF 인터랙티브 텍스트 레이어 연동**: `pdfjs-dist` 위에 인터랙티브 텍스트 레이어를 정밀하게 얹어, PDF 뷰어 안에서 **원클릭 밑줄 긋기 및 강조 표시**가 가능하도록 편의 기능을 추가했다.
- **원기호 및 특수 기호 시각 하이라이트**: 선지 번호와 본문 내 참조 기호를 시각적으로 또렷하게 보정하여, 눈을 찡그리지 않고도 0.1초 만에 문항 구조를 인지할 수 있게 지원했다.

## 4. 하루 8,000건을 폭증시킨 진짜 엔진: '5단계 검수 자동화 파이프라인'

마법봉과 스마트 매칭 같은 개별 기능이 아무리 훌륭해도, **교재 한 권을 볼 때마다 목록으로 나갔다 들어왔다 하고, 상태 변경 페이지를 따로 찾아가고, 메타데이터 화면을 다시 켜야 한다면 하루 8,000건은 결코 달성할 수 없었다.**

작업자가 화면 이곳저곳을 돌아다니며 길을 잃지 않도록, 오늘 검수할 자료들을 한 바구니에 쓸어 담아 **단 하나의 레일 위에서 일직선으로 완주하는 5단계 검수 자동화 파이프라인**을 구축했다:

```
[STEP 1: 대상 고르기] ──► [STEP 2: ITEM 검수] ──► [STEP 3: 단계 변경] ──► [STEP 4: METADATA 검수] ──► [STEP 5: 적용 확인]
 (오늘치 큐 일괄 적재)     (마법봉 + ⌥→ 논스톱)    (작업 상태 일괄 승격)    (룰 & 엑셀 스마트 매칭)    (최종 검증 및 완료)
```

* **STEP 1 (대상 고르기)**: 대시보드에서 오늘 검수할 자료들을 필터링해 클릭 한 번으로 로컬 영구 큐(`Zustand/persist`)에 일괄 적재한다.
* **STEP 2 (ITEM 논스톱 검수)**: 큐에 담긴 수십 건의 교재를 목록 이탈 없이 마법봉과 `⌥ →` 단축키로 연속 검수한다.
* **STEP 3 (단계 변경)**: 검수가 끝난 자료들의 작업 상태를 한 화면에서 일괄 승격한다.
* **STEP 4 (METADATA 검수)**: 룰 엔진과 엑셀 퍼지 매칭으로 출처/메타데이터를 큐 순서대로 일괄 바인딩한다.
* **STEP 5 (적용 확인)**: 최종 검증과 함께 검수 완료 리포트를 일괄 생성하고 마친다.

화면 전환과 메뉴 탐색 비용이 0으로 수렴하면서, 마법봉과 단축키의 시너지가 100% 폭발하여 **하루 8,000개 문항이라는 압도적인 처리량이 현실이 되었다.**

## 결과: 하루 1,000건에서 8,000건으로 8배 폭증한 생산성

* **일일 검수량 8배 폭증 (1,000건 → 8,000건)**: 분산된 화면을 5단계 검수 자동화 파이프라인으로 통합하고 불 켜진 마법봉 원클릭 일괄 교정을 결합한 결과, 기존 숙련 작업자의 하루 한계치(1,000건)를 훌쩍 뛰어넘어 **혼자서 하루 최대 8,000건의 문항을 처리**하는 압도적 생산성을 달성했다.
* **동선 낭비 및 수기 대조 비용 제로화**: 화면 간 이동을 없앤 5단계 레일과 엑셀 스마트 매칭을 통해 수기로 출처를 대조하고 복사/붙여넣기하던 비효율을 완벽히 제거했다.
* **작업 피로도 대폭 경감**: PDF 시각 보조 도구(밑줄/원기호 보정)와 눈이 편안한 웜 브라운 디자인 시스템을 통해 8시간 연속 작업 시 작업자의 눈 피로와 피로도를 획기적으로 낮췄다.

## 회고: 진정한 엔지니어링은 사용자의 번거로움을 끝내는 것이다

직접 실무자가 되어 하루 종일 화면을 붙잡고 일해보지 않았다면, "어드민이 원래 좀 번거롭지"라며 그냥 넘어갔을지도 모른다.

하지만 내가 직접 사용자가 되어 현장의 고통을 겪어보았기에, 작업자를 멈칫거리게 만드는 1초의 텍스트 탐색과 불필요한 마우스 동선이 모여 얼마나 거대한 비효율을 낳는지 절감할 수 있었다.

화려한 기술을 뽐내는 것보다 훨씬 중요한 것은, **사용자가 겪는 가장 번거롭고 고통스러운 지점을 집요하게 찾아내 '단 하나의 레일 위에서 불 켜진 마법봉으로 끝나는 직관적인 도구'로 탈바꿈시키는 집념**임을 가슴 깊이 배운 값진 프로젝트였다.
