Strapi 3.x 프레임워크에서는 하나의 데이터 모델에 라이프사이클 훅 객체를 딱 하나만 등록할 수 있다. 두 번째 훅을 등록하는 순간, 에러 한 줄 없이 첫 번째 훅이 조용히 덮어씌워져 사라져버린다.

공공기관 내부 업무포털 백엔드를 개발할 때였다. 보안과 컴플라이언스가 극도로 중요한 시스템이었기에, 모든 컬렉션의 생성·수정·삭제 내역을 전사 감사 로그(`collection-history`) 테이블에 영구히 남겨야 했다.

하지만 특정 모델들은 감사 로그 기록만으로 끝나지 않았다:
- 실시간 침해 알람 모델: 데이터가 생성되는 즉시 Socket.io를 통해 담당자 브라우저로 실시간 푸시 알림을 쏴야 했다.
- 보안 자산 모델: 데이터베이스에 영속화되기 직전에 외부 시스템과의 연동을 위한 데이터 정규화 가공을 거쳐야 했다.

즉, **전사 공통 감사 훅**과 **모델별 고유 비즈니스 도메인 훅**이 동일한 모델의 동일한 라이프사이클 이벤트(`afterCreate`, `beforeUpdate`)에 공존해야만 했다.

## 1. 문제: 덮어쓰기 버그와 20개 모델의 복붙 지옥

감사 훅도 `afterCreate`를 필요로 하고, 알림 훅도 `afterCreate`를 필요로 했다.

두 로직을 일반적인 모듈 방식으로 export하면 나중에 선언된 객체가 이전 객체를 완전히 덮어써 버렸다. 프레임워크가 런타임 에러를 뱉는 것도 아니었기에, 어느 날부터 특정 모델의 감사 로그가 슬그머니 누락되는 침묵의 데이터 결손이 발생하고 있었다.

이 문제를 피하겠다고 20여 개에 달하는 모든 모델 파일마다 감사 로깅 코드를 손으로 일일이 복사해 도메인 훅 안에 끼워 넣는다면:
1. 감사 로깅 정책이 20군데로 파편화된다.
2. 정책이 바뀔 때마다 20개 파일을 하나하나 열어 똑같이 수정해야 한다.
3. 신규 모델을 추가할 때 실수로 감사 코드를 빠뜨리면 그 모델만 감사 추적이 영구히 끊긴다.

## 2. 해결책: 다중 훅을 단일 파이프라인으로 합성하는 `combineLifecycles`

모델마다 코드를 복붙하는 대신, **여러 개의 독립된 라이프사이클 훅 객체를 전달받아 단일 실행 파이프라인으로 합성해 주는 고차 함수**(`combineLifecycles`)를 설계했다:

```js
// api/helper.js — 다중 라이프사이클 훅을 합성하는 파이프라인 헬퍼
const combineLifecycles = (lifecycleArray) => {
  const dividedCycles = {};
  const mergedLifecycle = {};

  // 1. 동일한 이벤트 키(beforeCreate, afterUpdate 등)별로 콜백을 배열로 수집
  lifecycleArray.forEach((item) => {
    for (const key in item) {
      (dividedCycles[key] ||= []).push(item[key]);
    }
  });

  // 2. 각 이벤트를 "배열 내 모든 콜백을 순차 호출"하는 단일 핸들러 함수로 재조립
  for (const key in dividedCycles) {
    mergedLifecycle[key] = async (result, params, data) => {
      for (const fn of dividedCycles[key]) {
        await fn(result, params, data);
      }
    };
  }

  return mergedLifecycle;
};
```

이 헬퍼를 도입하자 각 모델 파일은 놀랍도록 선언적이고 깔끔해졌다:

```js
// api/alarm/models/alarm.js
module.exports = {
  lifecycles: combineLifecycles([
    makeCollectionHistoryHooks('alarm'), // ① 전사 공통 감사 로그 훅
    {
      async beforeCreate(data) {
        // ② 도메인 로직: 유저명 → ID 변환
      },
      async afterCreate(result) {
        // ③ 도메인 로직: Socket.io 실시간 담당자 푸시
        strapi.io.emit('NEW_ALARM', result);
      },
    },
  ]),
};
```

## 3. 결과

* **20개 전사 컬렉션의 완벽한 감사 추적**: 게시판, 점검 결과, 사용자, 보안 자산 등 20여 개 모델에 단 한 줄의 감사 로그 누락 없이 안전하게 훅이 안착되었다.
* **단일 진실 공급원(SSOT) 확립**: 감사 로그 포맷이나 저장 규칙이 변경되더라도 `makeCollectionHistoryHooks` 헬퍼 한 곳만 수정하면 전사 20개 모델에 일괄 반영되는 유지보수성을 확보했다.

## 4. 회고: 프레임워크의 제약을 우아한 합성으로 극복하다

프레임워크가 제공하는 기본 기능이 팀의 아키텍처 요구사항(관심사 분리, 횡단 관심사 공통화)을 받쳐주지 못할 때, 가장 위험한 선택은 각 파일마다 중복 코드를 덕지덕지 복사해 넣는 것이다.

Strapi의 단일 훅 한계를 인정하고 **함수형 합성(Function Composition)** 패턴을 통해 '공통 관심사(감사)'와 '핵심 비즈니스(도메인)'를 완전히 분리해 낸 덕분에, 프로젝트가 끝날 때까지 단 한 건의 감사 데이터 유실 없이 견고한 백엔드 시스템을 유지할 수 있었다.
