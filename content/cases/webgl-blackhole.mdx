{/* 개인 사이드 프로젝트: WebGL Black Hole. */}

영화 *인터스텔라*의 거대한 블랙홀 '가르강튀아(Gargantua)'를 본 사람이라면, 빛이 도넛처럼 둥글게 휘어지며 암흑 속으로 빨려 들어가는 장면에 압도당했을 것이다.

"저 아름답고 기괴한 왜곡 효과를 웹 브라우저에서 내 손으로 직접 구현해 볼 수 없을까?"

그렇게 호기롭게 시작했다. 처음엔 일반상대성이론과 중력 렌즈 방정식을 다룬 광선 추적(Ray Tracing) 논문들을 뒤적였다. 하지만 물리 수식 몇 줄을 읽자마자 조용히 창을 닫았다. 

애초에 학술 논문을 웹에 재현하는 것이 목적이 아니었다. Three.js 같은 고수준 라이브러리 없이, **Raw WebGL 1.0과 GLSL 프래그먼트 셰이더를 밑바닥부터 제어하며 보는 사람을 시각적으로 설득하는 진짜 블랙홀 같은 룩**(Look)을 만드는 것이 목표였다.

물리적으로 엄밀한 빛의 궤적이 아니라, **화면 좌표계에서 극적으로 빨려 들어가는 시각적 마법**을 만들기로 방향을 틀었다.

## 1. 우주가 없으면 직접 그린다: Canvas 2D + WebGL 하이브리드

블랙홀 왜곡 효과가 극적으로 보이려면 뒤편에 빽빽하게 깔린 우주와 별빛 배경이 필수적이었다.

처음에는 고화질 우주 사진을 찾아 헤맸다. 하지만 막상 셰이더 왜곡을 먹여보니, 성운(Nebula) 색이 짙거나 배경이 밝은 사진은 별이 휘는 게 아니라 배경 텍스처 전체가 멀미 나듯 출렁거렸다. 게다가 정지된 사진 위에 블랙홀 혼자 도는 모습은 어딘가 부자연스러웠다.

결국 **별 배경 자체를 런타임에 직접 생성하고 움직이기로 결정**했다:
- 흰색을 기본으로 푸른 별, 붉은 별의 색온도를 섞고
- 크기 분포를 무작위로 조절하며
- 큰 별에는 방사형 그라디언트(Radial Gradient) 후광을 씌워 천천히 흐르는 프로시저럴 우주를 만들었다.

수천 개의 별 입자 분포와 후광 연출을 빠르게 실험하기 위해, **별판은 Canvas 2D로 렌더링하고, 이 캔버스를 매 프레임 WebGL의 텍스처로 업로드(`gl.texImage2D`)하여 셰이더로 왜곡하는 2-레이어 하이브리드 아키텍처**를 선택했다.

매 프레임 CPU에서 GPU로 픽셀을 전송하는 비용이 발생하지만, 캔버스 크기에서 60fps를 안정적으로 유지하면서 화려한 별빛 연출을 빠르게 구현할 수 있는 실용적인 엔지니어링 트레이드오프였다.

## 2. GLSL 셰이더: 일부러 '틀린' 회전 행렬을 먹이다

왜곡의 핵심은 단 한 장의 프래그먼트 셰이더(`blackholeShaders.ts`) 안에 담겼다. 중심점으로부터의 거리에 따라 당김(pull)을 계산하고, 그 당김을 회전각으로 삼아 배경 좌표계를 비트는 원리다.

```glsl
// 1. 역제곱 당김 계산 (+0.001 epsilon으로 0으로 나누기 방지)
float pull = (u_mass / (dist * dist + 0.001)) * falloffFactor;

// 2. 의도적으로 "틀린" 회전 행렬 적용:
// 정석적인 회전(동일한 각도) 대신, 서로 다른 위상을 먹여 전단(shear/비틀림) 왜곡을 합성
vec2 r = rotate(mouseUv, uv, pull);
```

이 셰이더에는 몇 가지 중요한 시각적 테크닉이 숨어 있다:

1. **0으로 나누기 방지 (Epsilon)**: `dist * dist + 0.001`에서 `+0.001` 엡실론이 없으면, 블랙홀 정중앙(`dist = 0`)에서 분모가 0이 되어 화면 전체가 검게 깨지거나 폭발한다.
2. **의도적으로 비튼 회전 행렬**: 표준 2D 회전 변환은 `cos(θ)`와 `sin(θ)`에 동일한 각도 `θ`를 사용해야 한다. 하지만 여기서는 `cos(angle * PI)`와 `sin(angle * 0.5)`로 서로 다른 위상을 주었다. 표준 회전이 아닌 **강력한 전단(Shear) 비틀림**이 섞이면서, 빛이 중심 소용돌이 속으로 격렬하게 빨려 들어가는 압도적인 흡입력이 연출되었다. 물리적 정석은 아니지만 시각적 완성도를 위한 의도적 선택이었다.
3. **부드러운 감쇠 (Smoothstep Falloff)**: 왜곡 반경 경계를 단순한 `if (dist > radius)`로 끊으면 경계면에 딱딱한 원형 칼자국이 남는다. `1.0 - smoothstep(0.0, radius, dist)`를 적용하여 왜곡이 우주 배경 속으로 부드럽게 녹아들도록 처리했다.

## 3. 가장 큰 난관: 레티나 디스플레이(DPR)의 좌표계 유령

셰이더 수식보다 개발자를 가장 지독하게 괴롭힌 것은 **레티나(`devicePixelRatio > 1`) 고해상도 디스플레이에서의 좌표계 불일치 버그**였다.

맥북 화면에서 실행하면 블랙홀의 왜곡 중심점과 마우스 위치가 묘하게 어긋나고, 텍스처 스케일이 제각각으로 늘어나는 현상이 발생했다.

원인을 파고들어 보니 두 캔버스가 해상도를 정의하는 방식이 완전히 달랐다:
- **Canvas 2D (별판)**: 물리 픽셀(`canvas.width = rect.width * dpr`)에 `ctx.scale(dpr, dpr)`을 먹이고 있었고,
- **WebGL 캔버스**: 뷰포트를 `gl.drawingBufferWidth` 기준으로 잡고 있었다.

하나의 캔버스를 다른 캔버스의 텍스처로 올리는 구조에서 두 좌표계의 배율이 어긋나니, 마우스 히트 좌표, UV 텍스처 매핑, 셰이더 왜곡 중심이 전부 미세하게 틀어졌던 것이다.

해결은 명료했다. **두 레이어 모두 `getBoundingClientRect()` 기반의 논리 해상도로 통일하고 불필요한 DPR 스케일링을 과감히 걷어냈다.** 텍스처 필터링을 `gl.NEAREST`로 설정하여 보간으로 인한 별빛의 뭉개짐을 막고 선명하고 또렷한 픽셀을 챙겼다.

## 4. 60fps를 사수하기 위한 3가지 퍼포먼스 최적화

수천 개의 별이 흐르고 마우스 조작에 따라 실시간 왜곡이 일어나는 환경에서, 버벅임 없는 60fps를 유지하기 위해 렌더링 파이프라인 전반을 최적화했다:

1. **셰이더 분기문(Branching) 제로화**:
   GLSL 셰이더 내부에서 `if/else` 분기문은 GPU 워프(Warp) 단위의 실행 효율을 심각하게 떨어뜨린다. 왜곡 반경 판단과 감쇠 처리를 조건문 없이 `smoothstep`, `clamp`, `mix` 등 GPU 내장 벡터 연산 함수로만 100% 풀어내어 픽셀당 연산 비용을 극소화했다.

2. **React 렌더 트리와 RAF 게임 루프의 완전 격리**:
   초당 60회 실행되는 `requestAnimationFrame` 루프 안에서 React의 상태(`useState`)나 가상 DOM이 개입하면 치명적인 가비지 컬렉션(GC) 병목이 발생한다. 마우스 위치 추적, 선형 보간(LERP) 물리 연산, WebGL 드로우 콜을 순수 JS `ref`와 클로저 내부에서만 완결 짓고, React는 마운트/언마운트 생명주기 제어에만 관여하도록 아키텍처를 분리했다.

3. **선형 보간(LERP) 기반의 부드러운 인터랙션과 슬라이더 디바운스**:
   마우스 클릭 시 블랙홀 좌표가 즉시 튀지 않고 `pos += (target - pos) * 0.02` 선형 보간으로 부드럽게 유영하도록 처리하여 프레임 드랍 없는 자연스러운 모션을 구현했다. 또한 별 개수 조절 슬라이더 조작 시 매 틱마다 캔버스가 파괴·재생성되는 부하를 막기 위해 250ms 디바운스를 적용했다.

## 결과

* **Pure WebGL 60fps 달성**: Three.js 등 무거운 라이브러리 없이 순수 WebGL 1.0 API로 셰이더 컴파일부터 버퍼, 유니폼, 텍스처 바인딩까지 직접 구현하여 안정적인 60fps 렌더링을 달성했다.
* **인터랙티브 생명주기 캡슐화**: React 19 커스텀 훅(`useBlackHole`)으로 렌더링 루프와 마우스 인터랙션을 깔끔히 격리하여, 클릭한 지점으로 블랙홀이 천천히 유영하듯 따라오는 몰입감 있는 씬을 완성했다. (현재 이 포트폴리오 사이트에 배포되어 직접 체험할 수 있다.)

## 회고: '물리적 엄밀함'보다 중요한 '시각적 설득력'

컴퓨터 그래픽스와 셰이더의 세계에서는 "물리적으로 100% 완벽한 공식"보다 **보는 사람에게 그럴듯한 감동을 주는 시각적 연출**이 먼저일 때가 있다.

일부러 틀리게 설계한 회전 행렬이 단순한 물리 시뮬레이션보다 훨씬 더 압도적인 빨려듦을 만들어냈듯이, 엔지니어링의 묘미는 현실의 복잡한 물리 법칙을 브라우저라는 제한된 캔버스 위에서 얼마나 영리하게 속이고 재해석하느냐에 있었다.

동시에 사이드 프로젝트를 진행하며 성능과 개발 속도 사이의 균형점을 어디에 둘 것인가 — 텍스처 업로드 비용을 감수하고 Canvas 2D의 유연성을 취할 것인가, 완전한 GPU 인스턴싱으로 갈 것인가 — 를 스스로 판단하고 선택하는 실용적인 엔지니어링 시야를 넓힐 수 있었던 귀중한 경험이었다.
